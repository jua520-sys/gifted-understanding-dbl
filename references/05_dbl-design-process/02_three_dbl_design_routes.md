# Three DBL Design Routes｜三個完整 DBL 設計路徑

## 1. Purpose

本檔案規定本 Skill 在使用者已經完成核心課程判斷後，
如何產生三個完整、可比較的 DBL 6½ Design Routes。

本功能的目的不是替使用者自動決定最佳教案，
而是提供三個具有實質設計差異的候選方案，
讓使用者比較：

- 課程對位
- 學科真實性
- 資優挑戰品質
- 學生決策空間
- 證據品質
- 修訂可能性
- 實施可行性

使用者保有最終選擇與修改權。

---

## 2. Activation Gate

只有在以下條件大致清楚後，
才啟動三方案輸出：

- 領域已確認
- 年級／學習階段已確認
- 正式課綱依據已確認
- Big Idea 已確認或高度穩定
- 關鍵理解 KU 已選定
- 主核心問題 EQ 已選定
- 資優加深加廣方向已初步形成

若上述核心尚未穩定，
不得直接生成三個完整 DBL 方案。

應先回到前一步完成判斷。

---

## 3. Shared Core Across All Three Routes

三個方案原則上共同保留：

- 同一正式課綱核心
- 同一 Big Idea
- 同一 KU
- 同一主 EQ
- 同一核心理解要求
- 同一主要學習證據方向
- 可比較的共同品質標準

三個方案的差異，
主要應發生在：

- 問題如何被界定
- 挑戰如何形成
- 學生如何作決策
- 真實限制是什麼
- 如何取得回饋
- 如何產生證據
- 如何迭代修正
- 如何展開學科工作

因此：

三方案不是三套不同課程目標。

---

## 4. Route Difference Requirement

三個方案至少必須在以下項目中，
有兩項以上的實質差異：

- Problem Framing｜問題界定
- Challenge Structure｜挑戰結構
- Student Agency｜學生決策
- Constraints｜限制條件
- Evidence Use｜證據使用方式
- Feedback Source｜回饋來源
- Iteration Pattern｜迭代方式
- Disciplinary Work｜學科工作
- Audience / User｜受眾或使用者
- Authentic Context｜真實／擬真情境

若三個方案只是：

- 海報
- 影片
- 簡報

則判定為 FAIL。

若只是：

- 換故事背景
- 換角色
- 換媒材
- 換地點

也不足以構成三個不同路徑。

---

## 5. Suggested Route Families

以下僅作生成靈感，
不得固定每次都使用同樣三類。

### Route A｜Evidence / Inquiry Route

核心特徵：

- 問題從證據不足或解釋競爭開始
- 學生需蒐集、比較、分析證據
- 挑戰重視建立解釋或判斷
- 修訂通常來自新證據

可能適合：

- 國語文
- 社會
- 自然科學
- 數學推理

---

### Route B｜Design / Decision Route

核心特徵：

- 問題涉及設計、選擇或限制
- 學生需提出方案
- 必須在條件下作出取捨
- 修訂通常來自測試與規準

可能適合：

- 數學建模
- 語文創作
- 科學與工程
- 社會政策設計

---

### Route C｜Authentic Action / Communication Route

核心特徵：

- 問題連結真實或擬真受眾
- 學生需對外溝通、提案、解釋或行動
- 回饋來自使用者、同儕、專家或利害關係人
- 修訂來自實際使用或回饋

可能適合：

- 社會
- 語文
- 特殊需求領域
- 跨領域設計

---

## 6. Do Not Force Route Families

Skill 不應每次機械輸出：

A 證據型
B 設計型
C 行動型

如果領域與 KU 不適合，
應形成更自然的三個方案。

例如：

數學可以是：

- 多策略比較型
- 建模限制型
- 猜想與反例型

國語文可以是：

- 閱讀解釋型
- 敘事結構設計型
- 讀者試讀修訂型

社會可以是：

- 多元觀點探究型
- 公共方案評估型
- 社區問題行動型

自然科學可以是：

- 解釋競爭型
- 模型建構型
- 實驗設計型

---

## 7. Required Output Structure

每一個 Design Route 必須完整呈現：

### Route Name
用一句能看出設計差異的名稱。

### Route Logic
用 2–4 句說明：

> 這個方案為什麼和另外兩個不同？

---

### Step 1｜什麼是我要教的

包含：

- 正式課綱核心
- Big Idea
- KU
- EQ
- Gifted Learner Horizon

三方案原則上維持同一核心。

---

### Step 2｜界定一個問題

回答：

- 學生要面對什麼問題？
- 為什麼值得處理？
- 問題如何連回 KU？

---

### Step ½｜提出前所未見的挑戰任務

回答：

- 學生要做什麼？
- 為誰做？
- 有哪些限制？
- 哪些地方必須自己決定？
- 為什麼不能直接複製現成答案？

---

### Step 3｜評定評量規準

至少包含：

- 3–6 個核心品質規準
- Must Have
- Must Avoid
- 初步證據蒐集方式

---

### Step 4｜讓學生嘗試

回答：

- 第一次要做什麼暫時模型／原型？
- 要留下什麼學習證據？
- 誰提供回饋？
- 學生如何做第一次自我評估？

---

### Step 5｜引導課程教學

回答：

- 第一次嘗試可能暴露什麼學習需要？
- 教師要教什麼？
- 哪些是全班共同需要？
- 哪些地方可能進入 DI？
- 使用哪些真正的學科工作？

---

### Step 6｜學生調整設計

回答：

- 學生要修改什麼？
- 必須根據什麼證據或回饋修改？
- 如何比較新舊版本？
- 如何說明修正理由？

---

## 8. Route Comparison Table

三個方案之後，
必須提供比較表。

比較至少包含：

| 比較面向 | Route A | Route B | Route C |
|---|---|---|---|
| KU 對位 |  |  |  |
| 學科真實性 |  |  |  |
| 資優挑戰品質 |  |  |  |
| 學生決策空間 |  |  |  |
| 學習證據清晰度 |  |  |  |
| 修訂潛力 |  |  |  |
| DI 銜接可能 |  |  |  |
| 實施負荷 |  |  |  |
| 主要風險 |  |  |  |
| 最適合條件 |  |  |  |

## 9. Route Recommendation Rule

Skill 可以做比較，
也可以提出：

> 「目前看起來 Route B 與 KU 對位最直接。」

但不得直接寫：

> 「你應該選 Route B。」

除非使用者明確要求推薦。

若使用者要求推薦，
應說明：

- 為什麼
- 依據什麼
- 犧牲了什麼
- 哪些條件改變後可能選另一方案

---

## 10. Gifted Challenge Gate

每個 Route 都要檢查：

1. 是否提供真正的質性挑戰？
2. 是否要求高層次理解？
3. 是否存在實質決策？
4. 是否允許多種合理路徑？
5. 是否能使用學生優勢？
6. 是否需要處理複雜性、不確定性或限制？
7. 是否需要修訂？
8. 是否比「更多、更快、更難」更有品質？

---

## 11. Disciplinary Authenticity Gate

每個 Route 都要問：

> 完成這個方案後，
> 學生是否更像一個會在該領域中思考的人？

例如：

### 國語文
學生是否真的在：

- 細讀
- 推論
- 詮釋
- 比較文本
- 有意圖地創作與修訂

### 數學
學生是否真的在：

- 推理
- 表徵
- 一般化
- 比較方法
- 找反例
- 建模

### 社會
學生是否真的在：

- 判讀資料
- 分析觀點
- 處理脈絡
- 評估方案
- 作公共判斷

### 自然科學
學生是否真的在：

- 提問
- 建立假說
- 控制變因
- 分析證據
- 建模
- 比較解釋

---

## 12. Evidence Gate

每個 Route 都必須能看見：

- 第一次想法
- 第一次作品／模型
- 推理
- 決策
- 回饋
- 新學習
- 修正
- 最終版本

若只能看見：

> 最後成品

則 DBL 證據鏈不足。

---

## 13. DI Connection Gate

每個 Route 都要預留：

Step 4
→ 取得 Evidence
→ 分析 Student Difference
→ Step 5 DI Response
→ Step 6 New Evidence

但不得在學生第一次嘗試前，
就機械預設固定高、中、低三組。

---

## 14. Feasibility Gate

三方案不能只比理論品質，
也要比較實施條件：

- 時間
- 學生年齡
- 教師準備量
- 可取得資源
- 場地
- 技術
- 真實受眾
- 回饋來源
- 課堂人數

高品質但無法實施的方案，
不能直接視為最佳。

---

## 15. Three-Route Quality Check

三個方案完成後，
Skill 必須檢查：

### Difference
三方案真的不同嗎？

### Shared Core
三方案仍然對準同一 KU 嗎？

### Challenge
每個方案都有質性挑戰嗎？

### Evidence
每個方案都能蒐集理解證據嗎？

### Iteration
每個方案都有真正修訂嗎？

### Agency
學生有實質決策嗎？

### Discipline
學生做的是領域工作嗎？

### Feasibility
教師真的有可能執行嗎？

---

## 16. Failure Patterns

### Fake Three Routes

A：做海報  
B：做影片  
C：做簡報

→ FAIL

---

### Different Topics

A 教比例  
B 教機率  
C 教幾何

→ 若核心 KU 不同，這不是同一核心的三條 DBL 路徑。

---

### Same Route, Different Decoration

三方案問題、挑戰、證據、回饋都一樣，
只有故事背景不同。

→ FAIL

---

### Different Difficulty Only

A 做 5 題  
B 做 10 題  
C 做 20 題

→ FAIL

---

### No Real Choice

三方案學生都只是按教師程序完成。

→ FAIL

---

## 17. Output Ending

三個方案完成後，
Skill 應停止在比較與教師判斷點。

最後詢問：

> 「你想保留哪一個 Design Route，
> 或希望把兩個方案的優點重新組合？」

不得自動進入完整教案製作。

---

## 18. Human Judgment Boundary

三方案的目的不是讓 AI 選課程。

AI 負責：

- 生成有品質的候選
- 說明差異
- 比較利弊
- 指出風險
- 檢查對位

使用者負責：

- 選擇
- 重組
- 修改
- 決定最終課程方向

這是本 Skill 的 Human-in-the-loop Gate。
